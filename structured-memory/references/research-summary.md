# Research Summary: Agent Memory Best Practices

Synthesized from parallel academic and industry research passes, then checked against primary sources — two mis-citations and one unverifiable statistic from the initial drafts were corrected or dropped before landing here (see the note at the bottom). Treat every claim below as source-checked, not as a raw research-agent transcript.

## Taxonomy

- Use a functional split into **working / episodic / semantic / procedural** memory as the primary partition, not "short-term vs. long-term." Working = the context window itself; episodic = concrete individual experiences (tool calls, turns, observations); semantic = abstracted, de-contextualized facts; procedural = reusable skills, rules, and executable plans. (Du, *Memory for Autonomous LLM Agents*, arXiv:2603.07670, 2026)
- A large 2025 survey goes further, arguing long/short-term framing is "insufficient" and proposing an orthogonal split of *function* (factual / experiential / working) against *form* (token-level / parametric / latent). (*Memory in the Age of AI Agents*, arXiv:2512.13564, Dec 2025)
- Domain shapes which type dominates. Personal-assistant agents lean semantic (preferences, profiles); coding agents lean procedural (verified patterns, architecture decisions) — directly relevant to a coding-focused agent's own memory practice.
- Type every memory and carry provenance as a first-class field, not an afterthought. MemOS's atomic unit, the "MemCube," bundles content with provenance and versioning metadata explicitly, because untyped stores let an agent confuse *who said this* with *what is actually true*. (MemOS, arXiv:2507.03724, Jul 2025; related narrower paper arXiv:2505.22101 — these are two distinct MemOS papers sharing overlapping authors, not one paper cited twice)
- Industry has independently converged on the same three durable categories — semantic / episodic / procedural — as a de facto standard, with procedural updated least often and semantic most. (LangChain/LangGraph memory docs, 2024–2025)

## Representation and structure

- A filesystem of named, editable documents beats an opaque embedding store for anything the agent needs to *surgically* edit rather than regenerate whole. Anthropic's memory tool is deliberately shaped as a filesystem (`view`/`create`/`str_replace`/`insert`/`delete`/`rename` under a `/memories` prefix), specifically so the agent can make targeted edits instead of rewriting a whole blob. (Anthropic, memory tool docs, 2025)
- Prefer many narrow documents over one large, continuously-growing profile. It's easier for a model to create a new object for new information than to reconcile it into an existing profile — at the cost of then needing dedup and retrieval across documents instead of within one. (LangChain/LangGraph, 2025)
- Give memory a hard size budget per topic instead of one shared pool. Letta's memory blocks pair a value with a description of *what belongs in it* and an explicit character cap, so the model can tell where a new fact goes and one topic can't silently crowd out another. (Letta, 2024–2025)
- Use a more rigid, structured format for content that must not casually drift. Anthropic reports the model is measurably less likely to inappropriately overwrite JSON than Markdown — specifically in the context of a persistent feature/test-status checklist, not as a blanket claim about all memory content. (Anthropic, *Effective harnesses for long-running agents*, 2025)

## Write discipline — the highest-leverage decision

- **Selective writes beat exhaustive writes.** Add-everything memory accumulation measurably degrades downstream accuracy as irrelevant records pile up, a pattern directionally corroborated by "context rot" — recall degrading as token count rises, a finding from external research (Chroma) that Anthropic's own engineering writing cites rather than originates — and by the *Lost in the Middle* results on degradation under long or cluttered context (Liu et al., Stanford, TACL 2024). Be deliberate about what earns a write, not exhaustive.
- **Score candidate writes on multiple factors** — recency, frequency, importance, salience, consolidation status — not similarity alone. (Chen & Cheng, *Learning What to Remember*, arXiv:2606.12945, Jun 2026, building on Park et al.'s Generative Agents retrieval scoring, Stanford 2023)
- **Write structured notes, not raw text blobs.** A-Mem generates a structured note per memory (context, keywords, tags) and links it to related existing notes, Zettelkasten-style — and lets a new note *update the attributes* of older related notes rather than leaving them frozen. (Xu et al., *A-Mem*, arXiv:2502.12110, Feb 2025)
- **Update by delta, not full rewrite.** ACE names two failure modes of naive full rewrites: brevity bias (drifts toward short, generic text, losing domain detail) and context collapse (repeated full rewrites erode detail over successive passes). Its fix is itemized, incrementally-updated bullets with separate Generator / Reflector / Curator roles, reporting +10.6% on its general "agents" benchmark category and separately claiming parity-or-better against the strongest production agent specifically on the AppWorld benchmark. (Zhang et al., *Agentic Context Engineering*, arXiv:2510.04618, Oct 2025)
- **Supersede, don't silently delete.** The strongest cross-source consensus found in this research: Zep closes a fact's validity window rather than deleting it on contradiction; Mem0's production pipeline is add-only, resolving conflicts at read time via recency ranking instead of destructive writes. Both reach "never destroy the record of what was previously believed" from opposite architectures. (Zep, arXiv:2501.13956, Jan 2025; Mem0 production notes, 2025–2026)

## Consolidation and decay

- **Consolidate episodic into semantic on a schedule**, keeping the episodic original rather than discarding it — repeated specific incidents ("corrected the date format on three separate occasions") become one semantic fact ("prefers DD/MM/YYYY"). (Park et al., Generative Agents, Stanford, 2023)
- **Decay by strength-with-reinforcement, not age alone.** The most-cited forgetting mechanism applies an Ebbinghaus-style exponential decay to memory strength, incremented every time the memory is actually recalled and used. (Zhong et al., *MemoryBank*, arXiv:2305.10250, 2023)
- **Give new memories a probation period before treating them as settled fact** — a "hot buffer" a single-observation write sits in before hardening into an authoritative long-term record, reducing the odds one noisy episode becomes permanent semantic "truth." (Du, arXiv:2603.07670, 2026)
- **Treat every compression pass as lossy, and instrument it** — each summarization silently drops low-frequency detail with no error signal, so know what a compaction pass discarded rather than assuming it was lossless. (Du, arXiv:2603.07670, 2026)
- **Run consolidation as background work, not inline** — Letta's "sleep-time" agents reorganize stored memory asynchronously during idle periods, improving both response latency and memory quality by taking reorganization off the hot path entirely. (Letta, 2025)

## Retrieval

- **Fuse multiple signals; never rely on similarity alone.** Every production system surveyed combines embedding similarity with at least one other signal — Mem0 fuses semantic + keyword (BM25) + entity linking; Zep combines embeddings + BM25 + graph traversal with zero LLM calls at retrieval time. (Mem0, 2025–2026; Zep, 2025)
- **Add graph/temporal structure specifically for multi-hop and time-sensitive queries.** Zep's bi-temporal graph tracks both when a fact was true in the world and when the system learned it, enabling point-in-time queries a plain vector store structurally cannot answer — "a pure vector store can return a stale fact and a current one with equal confidence." Reported gains: DMR accuracy 94.8% vs. MemGPT's 93.4%, and up to +18.5% on LongMemEval with roughly 90% lower latency than full-context baselines. (Zep, arXiv:2501.13956, 2025)
- Mem0 reports 92.5 (LoCoMo) and 94.4 (LongMemEval) at roughly 7,000 tokens per retrieval versus 25,000+ for full context — but these headline figures are from Mem0's own vendor documentation, not the arXiv paper itself, which reports different (lower) LoCoMo scores under a stricter judge (66.88 base / 68.44 graph-variant). Don't blend the two result sets as if they were the same measurement. On a dedicated temporal-reasoning category, Mem0's graph variant scored 58.13% versus 21.71% for OpenAI's own memory system on the same benchmark, with plain Mem0 itself at 55.51% on that category — its real lift over its *own* baseline is much closer to the ~2-point figure below than the OpenAI comparison alone suggests. At larger scale (Mem0's BEAM benchmark, vendor-reported only), accuracy drops to 64.1% at 1M tokens and 48.6% at 10M — small-benchmark scores don't necessarily hold at production scale.
- **Read the memory index before doing anything else, every session.** Anthropic's own injected guidance for its memory tool states almost exactly this: view the memory directory first, before any other action — a cheap directory listing doubles as a retrieval index. (Anthropic, memory tool docs, 2025)
- **Passing a recall benchmark isn't the same as using the memory.** Models scoring near-perfectly on straightforward recall benchmarks have been shown to fall to 40–60% on benchmarks that test whether retrieved memory actually changes a decision — evaluate whether an agent *acts* on what it retrieves, not just whether it can quote it back. (Du, arXiv:2603.07670, 2026, citing MemoryArena)

## Failure modes to design against

- **Memory accumulation alone can degrade safety, with no adversary involved.** A 2026 safety study found memory-induced policy-violation rates exceeding a no-memory baseline across eight different architectures on purely benign, non-adversarial data streams — driven by stale corrections silently overriding current ones, summarization merging separate facts into unwarranted specificity, and safety instructions being diluted by volume. (Al-Tawaha et al., *Remembering More, Risking More*, arXiv:2605.17830, May 2026)
- **Memory is a persistence channel for attacks delivered through completely ordinary input** — no privileged access required, and the payload passes as legitimate content, so input filtering alone does not defend against it. Reported techniques achieve very high injection/attack success at very low poison rates against both flat and graph-structured memory stores. (arXiv:2512.16962; arXiv:2601.05504, 2025–2026)
- **Write and eviction failures are silent** — there is no exception when a bad memory gets written or a good one gets evicted, just a slightly worse response with no stack trace pointing at the cause. Instrument the write path deliberately rather than trust that failures will be visible. (Du, arXiv:2603.07670, 2026)
- **A false reflective conclusion can block its own future correction** — self-generated reflective memory can entrench an error precisely because the agent stops re-testing a belief it has already "concluded." (Du, arXiv:2603.07670, 2026)

## Security, privacy, and enforcement boundaries

- **The harness enforces hygiene; the agent judges salience.** Across every system surveyed, self-editing memory (deciding *what* is worth keeping) is left to the model, while size caps, path validation, and sensitive-data stripping are enforced by the surrounding handler code, not by asking the model to police itself. Anthropic's memory tool explicitly validates and canonicalizes file paths against traversal attempts, and notes the model "usually refuses" to write secrets but recommends handler-side stripping "for stronger guarantees" rather than relying on that refusal alone. (Anthropic, memory tool docs, 2025)
- **Split explicit, user-editable memory from implicit inferred context, and make each independently revocable.** OpenAI's ChatGPT memory keeps user-visible "saved memories" separate from implicit "reference chat history," and saved memories persist even if the source chat is deleted. (OpenAI, 2024–2025)
- **Namespace isolation, not a shared store with a tag, is the converged pattern** for keeping memory from leaking across unrelated contexts — a flat, globally-shared memory has been reported causing an agent to apply one project's conventions to an unrelated one. (2025–2026 practitioner reports)

## Open disagreements worth knowing about

- **Graph vs. vector memory is genuinely unsettled**, and some of the loudest evidence is vendor-published. Zep and Mem0's graph variant both report gains from graph structure on temporal/relational queries, but Mem0's own internal ablation found its graph variant added only about 2 percentage points over its flat-store baseline on the same benchmark — a useful calibration on how much a graph actually buys versus how much complexity it costs.
- **Nobody has an accepted way to evaluate whether forgetting was correct.** Decay-rate and eviction-threshold choices across current systems are effectively unvalidated hyperparameters — a 2026 survey states this directly.

## Benchmarks worth knowing by name

LoCoMo, LongMemEval, DMR, MemBench, MemoryAgentBench (includes selective forgetting as a competency), MemoryArena, BEAM (large-scale, 1M–10M token regime).
